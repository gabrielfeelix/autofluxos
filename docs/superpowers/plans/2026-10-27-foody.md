# Foody Delivery: plano de implementação

**Goal:** o pedido despachado pela Foody entra no quadro, e quando o entregador sai o cliente recebe no WhatsApp o link para acompanhar no mapa.

**Fontes (27/out/2026):** `help.foodydelivery.com/knowledge-base/foody-delivery-api-v1-2/` e `.../foody-delivery-webhooks/`.

## Decisões

- **Opção A, do Gabriel (27/out):** a Foody é mais uma fonte de pedidos (`plataforma = 'foody'`, migration 0156). A tela orienta: se o cardápio já despacha pela Foody, conecte só a Foody, senão o pedido entra duas vezes. Juntar pedido de duas fontes pelo telefone foi descartado (erra a junção).
- **Modelo novo `aviso_pedido_saiu_rastreio`**, texto aprovado pelo Gabriel: "Seu pedido está a caminho! O pedido #{{1}} saiu para entrega. Acompanhe o entregador em tempo real pelo botão abaixo." Botão "Acompanhar entrega" → `https://app.foodydelivery.com/trk/{{1}}`. Fica fora de `MODELOS_DO_PEDIDO` para não cobrar conta sem Foody; sem ele aprovado, sai o `aviso_pedido_saiu_entrega`. Dentro das 24 h o texto ganha a linha "Acompanhe o entregador: <link>".

## API

- Token do lojista (Minha Conta > APIs e Hooks), no `Authorization` sem prefixo. Base `https://app.foodydelivery.com/rest/1.2`. Plano gratuito não tem API (403 E11).
- `GET /orders/{uid}`: `customer.customerPhone`, `orderTrackerUrl`, `deliveryPoint`, `orderDetails` (texto, sem itens separados).
- Listagem `GET /orders/?startDate&endDate` por data de **criação**, até 500: a passada lê as últimas 12 h e filtra por `updateDate`.
- Gatilho: o lojista cadastra URL e token (Minha Conta > Configurações Avançadas > Criar Gatilho). Payload `{ uid, updateDate, event: 'order_status_updated', token, status }`; `hook_test` ao salvar. Uma retentativa; 10 erros seguidos desligam o gatilho.

## Status

`open` → novo; `ready`, `dispatched`, `accepted` → em_preparo (entregador designado, ainda na loja); `onGoing` → saiu; `delivered`, `closed` → entregue; `cancelled` → cancelado; `rejected` e desconhecido → novo (não move).
