# OlaClick: plano de implementação

**Goal:** o lojista da OlaClick cola a chave de API, e todo pedido de lá entra no quadro de Pedidos, com o cliente avisado de cada etapa. Molde: `2026-10-27-cardapio-web.md`.

**Fonte:** documentação oficial `developers.olaclick.app` (Docusaurus; o schema de cada endpoint vem embutido no JS da página), lida em 27/out/2026.

## O que a documentação decidiu

- **Self-service com a chave do lojista**, gerada no painel em Integrações > API Keys (`olk_live_...`), em `Authorization: Bearer` ou `X-API-Key`. Planos pagos. O Hub (OAuth, várias empresas) fica para quando houver muitas lojas: exige homologação.
- Base `https://public-api.olaclick.app/v1`. Resposta em `{ data }`; erro em Problem Details (RFC 7807). Limite por chave, 429 com `Retry-After`.
- Escopos que pedimos ao lojista: `orders:read` (obrigatório), `webhooks:read` e `webhooks:write` (pedido na hora), `companies:read` (só o nome da loja na tela).
- **O webhook se registra pela API** (`POST /v1/webhooks`): o lojista não cola nada no painel de lá. Devolve `webhook_id` e `signing_secret`. Cada entrega vem com `X-OlaClick-Signature: sha256=<hex>` (HMAC do corpo cru). Eventos `ORDER_CREATED`, `ORDER_UPDATED`, `ORDER_DELETED`; o `data` é aviso, não fonte: o pedido é relido em `GET /v1/orders/{id}`. Retentativa até `max_retry` (pedimos 10), sem replay depois.
- Polling: `GET /v1/orders?filter[start_date]&filter[end_date]` (Y-m-d, obrigatórios), `filter[time_type]=updated_at` (no guia de webhooks), paginado de 50. O resumo traz `updated_at`; o completo é `GET /v1/orders/{id}`.
- **Telefone vem**: `client.phone_number` + `client.country_calling_code`, só no pedido completo.
- Valores em reais com decimais (`delivery_price: 6.5`).

## Mapa de status

| OlaClick (`status`) | Nosso |
|---|---|
| `INITIATED`, `PENDING` | `novo` |
| `PREPARING`, `CHECK_REQUESTED`, `CHECK_PRINTED` | `em_preparo` |
| `READY` | retirada: `saiu` (pronto para retirada); entrega: `em_preparo`, ou `saiu` se `delivery_status` já é `DELIVERING` |
| `DRIVER_ON_THE_WAY_TO_DESTINATION`, `DRIVER_ARRIVED_AT_DESTINATION` | `saiu` |
| `DELIVERED`, `FINALIZED` | `entregue` |
| `CANCELLED` | `cancelado` |

`service_type`: `DELIVERY` → entrega, `TAKEAWAY` → retirada, `ONSITE` → local, `TABLE` (mesa) → ignorado. Desconhecido fica `novo`.

## Onde cada coisa fica

- `idNaPlataforma` = `webhook_id` (a OlaClick não devolve id da empresa à chave); nulo = sem webhook, só a passada.
- `segredo_id` = `signing_secret` no Vault. Webhook sem segredo é recusado.
- `merchant_id` do webhook = `clienteId`.
- Conectar de novo apaga o webhook anterior antes de criar outro; desligar apaga o webhook lá, o segredo e a chave.
- Chave sem `webhooks:write` conecta mesmo assim, e a tela diz que os pedidos entram a cada 10 minutos.
